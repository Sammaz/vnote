# VNote 初始化任务可配置化需求规格书

## 1. 项目背景

VNote 是一个 AI 驱动的视频笔记桌面应用。当用户创建笔记后，系统会自动执行一系列初始化任务来生成笔记内容。

### 1.1 现有初始化任务（5个）

| 序号 | 任务名称 | 技术标识 | 说明 |
|------|---------|---------|------|
| 1 | 全文总结 | `full_summary` | 生成视频的整体摘要 |
| 2 | 原文细读 | `detailed_reading` | 基于字幕生成章节结构 |
| 3 | 高光笔记 | `highlights` | 提取视频精彩片段 |
| 4 | 推荐问题 | `suggested_questions` | 生成建议的问答列表（在全文总结完成后自动触发） |
| 5 | 闪记卡 | `flashcards` | 生成记忆卡片 |

### 1.2 需要新增的任务（1个）

| 序号 | 任务名称 | 技术标识 | 说明 |
|------|---------|---------|------|
| 6 | 字幕优化 | `subtitle_optimization` | 优化章节字幕文本，去除语气词并重组句子 |

## 2. 核心功能需求

### 2.1 任务配置功能（P0）

#### 2.1.1 可配置项

- **任务启用/禁用**：除"推荐问题"外，其他5个任务均可开启/关闭
- **任务执行顺序**：用户可自定义6个任务的执行顺序
- **"推荐问题"特殊处理**：始终启用，不可关闭，但可调整执行顺序

#### 2.1.2 默认配置

| 执行顺序 | 任务名称 | 默认启用 | 可禁用 |
|---------|---------|---------|--------|
| 1 | 全文总结 | ✅ | ✅ |
| 2 | 原文细读 | ✅ | ✅ |
| 3 | 字幕优化 | ❌ | ✅ |
| 4 | 高光笔记 | ✅ | ✅ |
| 5 | 推荐问题 | ✅ | ❌（必须启用） |
| 6 | 闪记卡 | ✅ | ✅ |

### 2.2 任务状态持久化（P0）

#### 2.2.1 存储信息

每个笔记的初始化任务状态需持久化以下信息：

```typescript
interface InitTaskState {
  note_id: number;                    // 笔记ID
  task_type: string;                  // 任务类型标识
  status: 'pending' | 'running' | 'completed' | 'failed' | 'skipped';
  started_at: string | null;          // 开始时间
  completed_at: string | null;        // 完成时间
  error_message: string | null;       // 错误信息（失败时）
  progress_current: number;           // 当前进度
  progress_total: number;             // 总进度
  generation_id: string | null;       // 生成任务ID（用于中止）
}

interface NoteInitProgress {
  note_id: number;
  config_snapshot: string;            // 任务配置快照（JSON）
  current_task_index: number;         // 当前执行到第几个任务
  overall_status: 'running' | 'completed' | 'failed' | 'paused';
  created_at: string;
  updated_at: string;
}
```

#### 2.2.2 状态更新时机

- 每个任务**开始时**：更新 `status='running'`，记录 `started_at`
- 每个任务**完成时**：更新 `status='completed'`，记录 `completed_at`
- 每个任务**失败时**：更新 `status='failed'`，记录 `error_message`
- 任务**被跳过时**：更新 `status='skipped'`

### 2.3 应用启动恢复功能（P0）

#### 2.3.1 启动检查逻辑

应用启动时（或窗口重新显示时）：

1. 查询数据库中 `overall_status = 'running'` 或 `'paused'` 的笔记
2. 对于每个未完成的笔记：
   - 恢复任务配置（从 `config_snapshot`）
   - 从 `current_task_index` 继续执行
   - 跳过已完成的任务

#### 2.3.2 恢复策略

- **正常恢复**：从中断点继续执行
- **失败重试**：失败的任务自动重试一次
- **用户干预**：如果重试仍失败，提示用户手动处理

### 2.4 设置页面UI（P1）

#### 2.4.1 新增标签页

在设置页面新增 **"初始化任务"** 标签页（或在 General 标签页下新增分组）

#### 2.4.2 UI 组件

- **任务列表**：显示6个任务，每个任务包含：
  - 拖拽手柄（用于排序）
  - 任务名称
  - 开关按钮（推荐问题显示但禁用）
  - 任务描述（可选）

- **交互方式**：
  - 拖拽排序：拖拽手柄调整执行顺序
  - 开关切换：点击开关启用/禁用任务
  - 实时保存：配置变更立即持久化

## 3. 任务依赖关系

### 3.1 强依赖

| 任务 | 依赖任务 | 说明 |
|-----|---------|------|
| 原文细读 | 全文总结 | 需要全文总结完成后才能生成章节 |
| 字幕优化 | 原文细读 | 需要章节数据才能优化字幕 |
| 高光笔记 | 原文细读 | 需要章节时长信息 |
| 推荐问题 | 全文总结 | 需要全文总结内容生成问题 |

### 3.2 依赖处理策略

- 如果用户禁用了某个任务，其依赖任务也应被自动跳过
- 在 UI 上显示依赖提示，帮助用户理解

## 4. 技术约束

### 4.1 后端（Rust/Tauri）

- 使用 SQLite 存储任务配置和状态
- 新增数据表：`init_task_configs`、`note_init_tasks`
- 新增 Tauri 命令：
  - `get_init_task_config` - 获取任务配置
  - `save_init_task_config` - 保存任务配置
  - `get_pending_init_tasks` - 获取待执行任务
  - `update_init_task_status` - 更新任务状态

### 4.2 前端（React/TypeScript）

- 在 `SettingsPage.tsx` 中新增任务配置 UI
- 重构 `NoteContentPanel.tsx` 中的初始化任务执行逻辑
- 使用 `@dnd-kit` 或类似库实现拖拽排序

## 5. 非功能性需求

### 5.1 性能

- 任务状态更新不应阻塞 UI
- 数据库写入使用异步操作

### 5.2 用户体验

- 配置变更即时生效（下次创建笔记时使用新配置）
- 提供清晰的任务进度反馈

### 5.3 兼容性

- 升级时自动迁移现有数据
- 默认配置保持与当前行为一致

## 6. 验收标准

- [ ] 用户可以在设置页面看到6个初始化任务
- [ ] 用户可以通过拖拽调整任务执行顺序
- [ ] 用户可以启用/禁用除"推荐问题"外的任务
- [ ] "推荐问题"任务始终显示为启用状态
- [ ] 新建笔记时按配置的顺序执行启用的任务
- [ ] 关闭应用后重新打开，未完成的任务自动继续执行
- [ ] 每个任务的状态正确持久化到数据库
